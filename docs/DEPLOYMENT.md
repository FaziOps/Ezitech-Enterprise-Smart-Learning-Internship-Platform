# Deployment Guide

Read the honesty note first, then follow the steps — they're accurate,
just not something I could execute myself in this environment.

## Why this is a guide and not a finished APK

This project was built without a Flutter/Android/Xcode toolchain
available, so:
1. **No native `android/`/`ios/` project scaffolding exists yet.** What's
   in this zip is Dart source + `pubspec.yaml` only. `flutter create`
   normally generates the native platform folders; that step needs to
   run in an environment with the Flutter SDK installed.
2. **Signing a release APK requires a keystore only you should hold.** A
   signing key is the one artifact in this entire project that must never
   be generated by an AI or committed to a repo — it's the equivalent of
   a password. I'm giving you the exact commands; you run them and keep
   the output private.

Follow the steps below in your own environment (or hand this file to
whoever has one) and you'll have a signed APK in about 20 minutes.

## Step 1 — Generate native project scaffolding

From the project root (where `pubspec.yaml` lives):

```bash
flutter create --platforms=android,ios --org com.ezitech.learning .
```

This generates `android/` and `ios/` in place. It will **not** touch
`lib/`. It may prompt to overwrite `pubspec.yaml` — say no, or back it up
first (`cp pubspec.yaml pubspec.yaml.bak`) and diff afterward to restore
your dependencies if it does get overwritten.

Then:

```bash
flutter pub get
flutter analyze   # confirm zero errors before going further
flutter test      # confirm the domain-layer test suite still passes
```

## Step 2 — Android signing

Generate a keystore (do this once, keep the file and passwords somewhere
safe — losing it means you can never update the app under the same
signing identity again):

```bash
keytool -genkey -v -keystore ~/ezitech-release-key.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias ezitech
```

Create `android/key.properties` (never commit this file — add it to
`.gitignore`):

```properties
storePassword=<the password you set above>
keyPassword=<the password you set above>
keyAlias=ezitech
storeFile=/absolute/path/to/ezitech-release-key.jks
```

In `android/app/build.gradle`, inside `android { ... }`, add a
`signingConfigs` block and point `buildTypes.release` at it:

```gradle
def keystoreProperties = new Properties()
def keystorePropertiesFile = rootProject.file('key.properties')
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}

android {
    // ...existing config...

    signingConfigs {
        release {
            keyAlias keystoreProperties['keyAlias']
            keyPassword keystoreProperties['keyPassword']
            storeFile keystoreProperties['storeFile'] ? file(keystoreProperties['storeFile']) : null
            storePassword keystoreProperties['storePassword']
        }
    }
    buildTypes {
        release {
            signingConfig signingConfigs.release
        }
    }
}
```

Build:

```bash
flutter build apk --release --dart-define=EZITECH_API_BASE_URL=https://your-real-api.example.com/v1
# or, for Play Store submission:
flutter build appbundle --release --dart-define=EZITECH_API_BASE_URL=https://your-real-api.example.com/v1
```

Output: `build/app/outputs/flutter-apk/app-release.apk`.

## Step 3 — iOS build configuration

You need a Mac with Xcode for this step — there's no way around that for
iOS, with or without an AI involved.

1. Open `ios/Runner.xcworkspace` in Xcode.
2. Under **Signing & Capabilities**, set your Team and confirm a unique
   Bundle Identifier (e.g. `com.ezitech.learning`).
3. Add required usage-description entries to `ios/Runner/Info.plist` —
   this app uses biometrics, camera-adjacent features, and background
   notifications:
   ```xml
   <key>NSFaceIDUsageDescription</key>
   <string>Unlock Ezitech quickly and securely with Face ID.</string>
   <key>NSCameraUsageDescription</key>
   <string>Used for QR attendance and profile photos (if enabled).</string>
   ```
4. Under **Signing & Capabilities**, add the **Push Notifications** and
   **Background Modes** (Remote notifications) capabilities for FCM.
5. Build:
   ```bash
   flutter build ios --release --dart-define=EZITECH_API_BASE_URL=https://your-real-api.example.com/v1
   ```
   Archive and upload via Xcode's Organizer for TestFlight/App Store, or
   run directly on a connected device for a local build.

## Step 4 — Firebase (required for Notification Center to do anything real)

1. Create a project at the Firebase console.
2. Add an Android app (package name must match
   `android/app/build.gradle`'s `applicationId`) → download
   `google-services.json` → place in `android/app/`.
3. Add an iOS app (bundle id must match Xcode's) → download
   `GoogleService-Info.plist` → add to `ios/Runner/` via Xcode (drag into
   the project, not just the file system, so it's added to the build
   target).
4. Android: add the Google Services Gradle plugin per Firebase's official
   Android setup docs for your Flutter/Gradle version — this step is
   version-sensitive enough that I'd rather point you at Firebase's
   current docs than hand-type a Gradle snippet that might be stale by
   the time you read this.
5. Without this step, the app still runs — `FcmService` detects Firebase
   isn't initialized and no-ops (see
   `features/notifications/data/datasources/fcm_service.dart`'s
   `_available` check) rather than crashing.

## Environment configuration

The API base URL is set via `--dart-define`, read in
`lib/core/network/api_client.dart`:

```dart
static const String baseUrl = String.fromEnvironment(
  'EZITECH_API_BASE_URL',
  defaultValue: 'https://api.ezitech.example.com/v1',
);
```

Pass it at build time (shown above) rather than hardcoding it, so
staging/production builds don't require a code change.

## CI

A minimal GitHub Actions workflow is included at
`.github/workflows/ci.yml` — runs `flutter analyze` and `flutter test` on
every PR, matching the Implementation Plan's Section 2.3 requirement.
It does not build or sign anything (that needs the keystore secret,
which should live in your CI provider's encrypted secrets store, not in
this repo).
